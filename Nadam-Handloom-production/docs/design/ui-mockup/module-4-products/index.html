How to review

Four things to try

Open the Design options panel (bottom right) at any time. Your changes stay in this browser until you press Reset demo.

Add a batch

Rainbow checks sarees → Add products → Choose photos → pick 8 → press "Free tag" for each → Save. Watch it save in the background.

Make a mistake

While scanning, press "Used tag", "Sold tag" or "Tag from photo 1". Press Undo last and Skip.

Fix a tag later

Open a saree, tap its tag: Change tag (wrong tag), Tag damaged (replace), Saree damaged.

Find a saree

Search 2264, or Scan to find. Switch rows / grid above the list. Turn on "No internet" and add a saree: it waits and uploads later.

One saree, one tag

Scanning a saree that already has a tag asks "Replace NH3301 with NH3302?". It never adds a second tag by accident, and there is no "Add another tag" (your pick A).

Wrong tag: Change tag

Damaged tag: Replace

Stick a new tag, scan it. The damaged number is retired, never used again. Same number reprinted? Nothing to do. A tag that won't scan can always be typed.

What this mock-up follows

  • Gallery + scan is the main way; Quick add for 1–3 sarees. "Same design, many tags" dropped: every handloom saree is different.
  • Delete never erases: gone from the app, website and counter; bills keep it; its unsold tag is free again. Refused while an online order holds it.
  • The name always follows the subcategory; price always comes from the subcategory.
  • One main photo when adding, fitted to the website's 3:4 card; up to 4 extra photos later.
  • Up to 50 photos per batch. Where it sells chosen once per batch. Details optional, never asked while adding.
  • The 5,000 limit counts only sarees in stock. Camera, typing or a Bluetooth scanner. Works offline; uploads later.
  • Your picks: product list = rows with photo, plus a rows / grid switch on the Products page that the phone remembers · scan screen = camera full, photo in a card (B) · one saree = one tag (A) · theme follows the phone.
Fixed from the old app

Content and behaviour fixes

  • 501 listings showed an old name on the website (90 of the sarees in this mock-up).
  • A used tag was found only when saving, and the whole saree had to be redone.
  • Tags couldn't be changed or replaced; deleting blocked a tag forever or erased orders.
  • The 5,000 limit counted sold-out listings, so it would block new sarees.
  • The app and the server tidied tags differently ("NH 001" vs "NH001").
  • Colour, fabric, border, occasion couldn't be set (0 filled in), though the website filters by them.

Not in this module

  • Selling at the counter (scan to sell): Module 5.
  • Invoices: Module 6. Online orders and shipping: Module 7.
