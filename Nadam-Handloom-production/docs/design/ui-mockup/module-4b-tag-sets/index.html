One photo, a set of sarees

The client's ask: a set of 5 identical sarees gets one photo and five tags, as in the old app. Each tag is still one saree in stock and sells on its own. This shows how it would work inside the new app's fast Add sarees flow, before any real code changes.

What the client means

A set of 5 identical sarees

The old app's New Product screen took one photo and a list of barcodes. The new app allows one tag per photo, so a set can't be added as one listing.

On 11 Oct "same design, many tags" was dropped because most handloom sarees are one of a kind. The client now needs it for sets of identical sarees, so this mock-up brings it back as an option on any photo.

How the app knows a photo is a set

All three are in the mock-up. Pick one in Design options ("Scanning a set"), or with the buttons below. Single sarees work as today in A and B.

A

Count first

Under the photo: "Sarees in this photo − 1 +". Tap + to 5, scan 5 tags; it moves to the next photo by itself after the 5th.

  • Single sarees stay exactly as fast as today.
  • The app knows the count, so it warns if a set is short.
  • Extra: tap + a few times for each set.
RecommendedTry A
B

Switch

Under the photo: "One saree | A set". In "A set", every scan adds a tag; tap Next photo when the set is done.

  • A simple either/or.
  • Extra: "Next photo" after each set.
  • Can't warn if a set is short (no count).
Try B
C

Keep scanning

No setting. Every photo stays until you tap Next photo; scan one tag or five.

  • Nothing to learn.
  • Extra: one more tap for every saree, even single ones (30 sarees = 30 extra taps).
  • Can't warn if a set is short.
Try C
Rules in this mock-up

How a set behaves

The one-tag-one-saree rules from 11 Oct all stay. What changes: a photo may now carry more than one tag.

Each tag is one saree

A set of 5 is one listing with 5 in stock. Selling one sells that tag only; the listing stays on the website until the last one sells. It counts once toward the 5,000 limit (listings in stock).

See it →

Checked tag by tag

Every tag of a set is checked the moment it's scanned: already used, sold, retired, on another photo. The same tag read twice is ignored.

See it →

Saved whole, or not at all

If one tag of a set was used on another phone meanwhile, none of the set is saved until that tag is replaced. Stock never ends up half-right.

See it →

Add more tags later

More of the same design came in? Open the set's page, "Add more tags", scan them. No new photo, no new listing. To confirm.

Before we build it

  • How a set is scanned: A (count first, recommended), B (switch) or C (keep scanning).
  • Tags on the check screen: A (every tag shown) or B (the count, tap for the list).
  • Up to 50 tags on one photo: enough? (The old app allowed 200.)
  • "Add more tags" later on a set's page, for restocking the same design: yes or no?
What stays the same

Unchanged

  • Subcategory once per batch; name and price from it. Gallery + scan, Quick add, saving in the background, offline.
  • Change tag, Tag damaged (replace), Saree damaged and Remove work on each tag of a set.
  • Delete never erases; all unsold tags of the set become free.
  • The 140 old listings with 2–6 tags keep working as sets.

Not in this mock-up

  • Selling at the counter (Module 5) already sells by tag; the sale here is pretend.
  • How the website shows a set's stock is checked when we build it.
