# Catalog area feature inventory: Nandam staff/admin app

> **Snapshot of the OLD admin app (`frontend/app`) and its backend, taken 2026-10-10 by reading the code.**
> Reference for the rebuild: what exists today, the rules it follows, and the gaps and bugs observed.
> Paths refer to the old code in `frontend/app/src/` and `backend/src/`. Do not edit this file to describe the new system.

I read every file you listed in full, plus the backend routes, services and Prisma models behind them. I edited nothing.

Short names used below: FE = `frontend/app/src`, BE = `backend/src`. All endpoints sit under `/api/v1`.

## 0. Who can do what

- **How users get into the catalog**
  - The Categories screen is linked only for the owner (ADMIN): from "Catalog" and "Update prices" on Admin Home (`AdminHomeScreen.tsx`) and from "Catalog" in More/Profile (`ProfileScreen.tsx`).
  - Staff have no menu path to Categories, Subcategories or Catalog PDF.
  - Products are open to everyone through the Products tab (`RootNavigator.tsx`). Products can also be opened from the "New product" quick action on Admin Home and from an order line in `OrderShipmentScreen.tsx`.
- **Rules enforced by the backend** (`catalog.admin.routes.ts`, `catalog-pdf.routes.ts`, `inventory.routes.ts`):
  - Categories: both roles can read; only ADMIN can create, edit or upload a photo.
  - Subcategories: both roles can read; only ADMIN can create, edit, delete, upload a photo, or change prices and visibility.
  - Products: ADMIN and STAFF can do everything, including delete and photo upload.
  - Catalog PDF: ADMIN and STAFF can check status and generate.
  - Scan lookup and piece lists: ADMIN and STAFF.
- **Read-only mode in the app:** the Category and Subcategory forms check `role === 'ADMIN'`. Anyone else sees the warning "Only the owner can make changes here", with inputs and switches disabled and the Save, Delete and Picture controls hidden. The product screens have no role checks.

## 1. Screens and features

### Categories list (`CategoryListScreen.tsx`)
- Lists all categories: thumbnail (or placeholder), name, "N subcategories · N products". The product count leaves out archived products (`listAllCategories` in BE).
- Order is position, then name.
- "+ New" opens a blank Category form; tapping a row opens it for editing.
- Reloads every time the screen gains focus.
- Offline: falls back to the last list cached on the phone and shows an offline banner with the date it was saved (`offlineCache.ts`, key `categories`).
- No delete, no hide, no search.

### Category form (`CategoryFormScreen.tsx`)
- Create: Name, Description, Position → "Add Category" → returns to the list. An info card says a photo and subcategories can be added after creation.
- Edit:
  - The category is found by loading the whole category list; there is no single-category GET.
  - Same three fields, plus a Picture card (owner only) and a "Subcategories" link card showing the count.
  - Photo: tap "Add Photo" or "Change Picture" → choose Take Photo or Library (`PhotoSourceSheet`) → resized to 1200px wide, JPEG quality 0.7 → preview with "New picture added. Tap Save to keep it." Nothing uploads until Save.
  - Save sends the details (PATCH) first, then uploads the photo. If the upload fails, the details stay saved, the photo stays staged and the error says to tap Save again.
- There is no category delete and no hide/unhide anywhere, front or back end.

### Subcategories list (`SubcategoryListScreen.tsx`)
- Reached from Category form → "Subcategories".
- Paged: 10 per page, infinite scroll (`usePagedList`); refreshes rows when you come back from a form.
- Search:
  - Runs on the server: name contains the text, case-insensitive.
  - Fires 300ms after typing stops; has a clear (x) button.
  - The search box is shown only once the category has at least one subcategory.
- Recent searches:
  - Up to 5, stored per user and per category (`recentSearches.ts`).
  - Shown when the empty box is focused; "Clear" empties them.
  - A search is saved only when submitted or when one of its results is opened.
- Each row shows:
  - Thumbnail, name, product count, a "Hidden" badge when hidden, a "Needs photo" badge when it has no photo of its own.
  - Store price.
  - A "Catalog PDF" link at the bottom of the card.
- "+ New" has no role check on the screen itself.

### Subcategory form (`SubcategoryFormScreen.tsx`)
- Create: Name, Description, Website price, Store price, Position → "Add Subcategory". The new subcategory is always visible on the website at first.
- Edit:
  - Loaded from the whole subcategory list for the category.
  - Same fields, plus a Picture card (owner only) and a "Show on website" switch.
  - The Picture card says "website shows an empty box" when there is no photo.
  - Photo flow is the same as the category form: staged locally, uploaded after the PATCH, retry if it fails.
- "Delete Subcategory" (owner only):
  - Confirmation explains that all its products and pictures are deleted, cannot be undone, and suggests switching off "Show on website" instead.
  - On success: "X and N products were removed."
  - If the server refuses, its message is shown on the form.

### Catalog PDF screen (`SubcategoryCatalogScreen.tsx`)
- Shows the current status: "Last generated <date>" and "N product photo(s)", or "No catalog PDF generated yet."
- If none exists: a "Generate Catalog" button.
- If one exists:
  - Android: customer mobile field, then "Share on WhatsApp".
  - iPhone: a plain "Share" button.
  - Both: a "Generate New" button.
- Generating and downloading need a connection; an offline banner is shown.
- Details in section 4.

### Product list (Products tab) (`ProductListScreen.tsx`)
- Header: "N live listings" and "+ New".
- Search: product name or SKU on the server. It runs only when the search is submitted; clearing the box restores the full list.
- Barcode icon opens the scanner:
  - Code found → opens that product.
  - Not found → dialog "No product found… Create a new product and attach it?" → opens the Product form with that barcode already added.
  - The lookup is exact here, so typing just the short number on a tag does not match.
- "N of 5000 listings live" with a progress bar (cap from the backend).
- Paged 10 at a time; pull to refresh; refreshes when you come back to it.
- Offline: the loaded unfiltered list is cached (key `products`) and shown when offline; infinite scroll is off while offline.
- Each row shows:
  - Photo, name, "SKU · Category › Subcategory", store price. The online price is deliberately never shown.
  - Stock badge: "Out of stock" in red at 0; amber when 3 or fewer; green otherwise. Wording is "N pieces" for barcode-tracked products and "N in stock" for quantity-tracked ones.
  - Visibility badge when not "both": Online only / Store only / Hidden.
  - "Inactive" badge when the product is inactive.

### Product form (`ProductFormScreen.tsx`)
- **Create** (owner and staff):
  1. Photo (required):
     - Take Photo or Library → "Crop & Rotate" editor.
     - Then resized to 1200px wide, JPEG quality 0.7, and staged.
  2. Category (required): searchable picker showing only active categories.
  3. Subcategory (required):
     - Searchable picker showing only visible subcategories.
     - Shows "Pick a category first" or "No subcategories yet" when there is nothing to pick.
     - Recently picked subcategories (up to 5, per user and category, `recentPicks.ts`) appear above the list.
     - Changing the category clears the chosen subcategory.
  4. A note shows the subcategory's store price: "change it in Categories".
  5. "Best Seller" switch (`isFeatured`).
  6. "Where does this product sell?" chips: Online + Store / Online only / Store only.
  7. Barcodes (at least one required):
     - Type a code and press return, or tap the barcode button to open the camera. The camera closes after one scan.
     - The camera button is disabled while the text field holds a code.
     - Each code is checked against the server with an exact lookup. Possible results: "Added X", "Barcode already used — on <product> (<status>)", or "already on this list".
     - The pending list shows each code with a remove (x).
  8. "Create Product":
     - Product and barcodes go in one call and one database transaction.

- **Delete** (owner and staff): confirmation, then "Product deleted". The server either archives or fully deletes (section 3).
- **Not on the form:**

  - All attribute fields.
  - Tracking mode (always `serialized` for new products; existing products keep their value).
  - `isActive` (loaded and sent back unchanged).

## 3. Business rules and edge cases already handled

### Delete vs archive
- **Subcategory delete** (`catalog.admin.service.ts` → `deleteSubcategory`):
  - Refused (409) if any product in it was part of a paid order (statuses processing, shipped or delivered) or has a sold piece. The message says to hide it instead.
  - Refused (409) while a checkout is holding stock for one of its products.
  - Otherwise permanently deletes, in one transaction: stock history, holds, unpaid abandoned orders, pieces, products and their images, and the catalog PDF record.
  - Stored image files are deleted after the database rows are gone.
- **Product delete** (`catalog.admin.service.ts` → `deleteProduct`):
  - Refused (409) only while an online checkout holds the product.
  - If it has sales history (a paid order, any store order, or a sold piece): **archived**. It is marked deleted, made inactive, and set to `hidden`. It disappears from the list, from scanning and from selling.
  - Otherwise it is fully deleted (stock history, holds, abandoned orders, pieces, images) and its barcodes become free again.
- **Category:** there is no delete endpoint (`catalog.admin.routes.ts`).

### Hiding and channel visibility
- **Hiding a subcategory** (`isActive=false`):
  - Removes the subcategory and all its products from the website (`catalog.service.ts` → `listSubcategoriesForCategory`, `buildProductWhere`).
  - It also disappears from the product form's picker (`ProductFormScreen.tsx`).
  - Showing or hiding is written to the audit log (`catalog.admin.service.ts`).
- **What the website shows** (`catalog.service.ts`): products that are active, set to `online_only` or `both`, in a visible category and subcategory, and in stock (old stock counter above 0, or at least one `in_stock` piece).
- **Online checkout** refuses products not set to `online_only` or `both` (`inventory.service.ts:79`).

### Duplicate names and IDs
- **Subcategory names:** the database rule is unique per category on the exact name. A duplicate gets a generic 409 "A record with these details already exists" (`schema.prisma`, `error.middleware.ts`).
- **Category names:** duplicates are allowed. The web address (slug) gets a "-2", "-3" suffix. Renaming a category creates a new slug (`catalog.admin.service.ts` → `uniqueSlug`, `updateCategory`).
- **Product name, slug and SKU:**
  - The name is shared freely.
  - The slug is unique with a -N suffix.
  - The SKU is `NH-<up to 4 initials of the category slug>-<3+ digits>`, one past the highest number used so far (`nextSku`).
  - When two phones save at once and clash, the server retries up to 5 times with a short random wait (`createProduct`).

### Reordering
- Positions run 1..n within each parent. Picking a position someone else holds swaps the two.
- Numbers past either end are moved to the end; old gaps or duplicate positions are cleaned up into 1..n (`displayOrder.ts` → `planReposition`).
- New rows go at the end, then move to the requested position. All position changes are one database statement inside a transaction (`catalog.admin.service.ts` → `applyPositions`).
- Blank or invalid input is never sent (`utils/sortOrder.ts`).

### Photos
- **On the phone:**
  - Category and subcategory photos: resized to 1200px wide, JPEG 0.7, no crop step (`CategoryFormScreen.tsx`, `SubcategoryFormScreen.tsx`).
  - Product photos: crop editor first, then the same resize (`ProductFormScreen.tsx`, `ImageEditorModal.tsx`).
- **Photos wait for Save:** nothing uploads until Save is pressed, because uploading replaces the live image on the website. If the upload fails, the other edits stay saved and the photo stays staged for retry (all three forms).
- **Upload transport** (`api/catalog.ts`):
  - Phones use expo-file-system multipart with field name `image`; web uses FormData.
  - On a 401 the app gets a fresh token and sends the photo again.
- **Server checks** (`catalog.admin.routes.ts`, `catalog.admin.service.ts`):
  - 8MB limit; JPEG, PNG or WebP only.
  - Error 503 `STORAGE_NOT_CONFIGURED` when image storage is not set up.
- **Server compression** (`utils/compressImage.ts`):
  - Every stored picture is a JPEG of 80KB or less.
  - Longest edge starts at 960px and steps down to 640px; quality steps from 70 to 42.
  - Rotation is applied and the photo's EXIF metadata (including location) is removed; transparency becomes white.
- **Replacing photos:**
  - One image per product; a new upload replaces the old one, and the old file is deleted from storage in the background.
  - Category and subcategory photos are replaced the same way.
  - Storage folders: `products/`, `categories/`, `subcategories/`, `catalogs/`.
- **No borrowed photos:** a subcategory shows only its own photo, never the category's or a product's. `hasOwnImage=false` drives the "Needs photo" badge (`catalog.admin.service.ts` → `listSubcategories`).
- **Storage backends** (`providers/storage/*`): S3 in production; a local folder served at `/uploads` for development; and a placeholder that reports "not configured".

### Barcodes and pieces
- New product with barcodes: the product and its pieces are created in one transaction, so a taken barcode cancels the whole creation. The app then removes only the taken codes from its list and names the product they belong to (`createProduct`, `claimPiecesForProduct`, `ProductFormScreen.tsx`).
- Server barcode checks (`inventory.service.ts` → `claimPiecesForProduct`; `utils/barcode.ts`):
  - Codes are stored in a standard form: spaces removed, upper case.
  - Duplicates within one batch are rejected with error code `DUPLICATE_IN_BATCH`.
  - Every equivalent retail-barcode form is checked (UPC-A, UPC-E, EAN-13 and the 14-digit form of the same code).
  - Each new piece writes a "restock" line to the stock history.
- Double scans and double taps in the pending list are blocked instantly by a synchronous claim set (`ProductFormScreen.tsx`, `ClaimSet`).
- Scan lookup (`inventory.service.ts` → `scanLookup`):
  - Matches piece barcodes first, then SKU.
  - When not exact, a bare number like "3136" also finds the tag "NANDAM3136". If several tags carry that number, the in-stock one wins, otherwise error `AMBIGUOUS_CODE`.
  - Archived products are never matched.
- The barcodes of an existing product cannot be edited (`updateProductSchema` leaves them out).

### Stock vs pieces
- Available count = old `stock` counter + number of `in_stock` pieces. It is computed for every product shown (`catalog.availability.ts`).
- `trackingMode` only changes how stock is labelled; it does not change any logic (`schema.prisma` comment).

### Listing cap
- At most 5000 active products. Creating or re-activating a product past that is refused (`ACTIVE_PRODUCT_CAP`, `assertActivationAllowed`).

### Audit log
Every catalog change is recorded (`catalog.admin.service.ts`, `catalog-pdf.service.ts`):
- category_created, category_updated, category_image_updated
- subcategory_created
- subcategory_price_changed (records before and after for online price, store price, MRP and description)
- subcategory_shown_on_web, subcategory_hidden_from_web
- subcategory_image_updated, subcategory_deleted
- product_created, product_updated, product_deleted (includes the barcodes and whether it was archived), product_image_updated
- subcategory_catalog_pdf_generated

## 4. Catalog PDF

### Generation (`catalog-pdf.service.ts`)
- Request: `POST /admin/subcategories/:id/catalog-pdf`, limited to 10 per minute.
- Which products get a page:
  - Active, not archived, have a photo, and are in stock (old stock counter + `in_stock` pieces above 0).
  - Ordered oldest first.
  - A product whose photo cannot be downloaded is skipped.
  - If no product qualifies, or no photo can be loaded, the server returns 400 with a message.
- Each page is A4 with one product:
  - Ivory background with a gold-bordered rounded white card.
  - Subcategory name in upper case, maroon, large serif, centred, with a gold divider and diamond.
  - "ID: <tag number>" underneath. This is the number after the letter prefix of each in-stock piece's barcode, comma-separated if there are several; codes without a letter prefix are shown in full.
  - The photo fills the rest of the page.
  - Deliberately no price, no shop name and no logo.
- Built with pdfkit; photos are downloaded on the server (`fetchImageBuffer.ts`).

### Storage
- Uploaded to storage under `catalogs/`.
- One record per subcategory, created or replaced each time (`SubcategoryCatalogPdf`: URL, file key, product count, generated at, generated by).
- The old file is deleted only after the new upload succeeds.
- The response is the raw PDF plus an `X-Product-Count` header.
- Status check: `GET /admin/subcategories/:id/catalog-pdf` returns the record, or nothing.

### In the app
- Generate (`api/catalogPdf.ts`, `SubcategoryCatalogScreen.tsx`, `utils/pdf.ts`, `utils/catalogShare.ts`):
  - 90-second timeout; one automatic token refresh and retry on 401.
  - The PDF is saved in the phone's cache as `Nandam-<Name-Slug>-catalogue.pdf`, replacing any earlier copy.
  - The status is then reloaded, and the local copy is tagged with its generation time.
- Share (`SubcategoryCatalogScreen.tsx`):
  - Reuses the phone's copy if it matches the latest generation; otherwise downloads it from the public URL, which needs a connection.
- **Android** (`utils/whatsappPdf.ts`):
  - Asks for the customer's mobile. It must be a valid 10-digit Indian number starting 6–9; +91 or a leading 0 are accepted (`cleanMobile` in `invoiceShare.ts`).
  - Opens WhatsApp Business if installed, otherwise WhatsApp, straight into the chat for 91<number> with the PDF attached.
  - Caption: "Nandam Handlooms – <name> catalogue. Please tell us the ID number of the piece you like."
  - Staff press Send in WhatsApp themselves.
  - Relies on a patched react-native-share (`patches/react-native-share+12.3.1.patch`).
  - With no WhatsApp installed: opens the system share sheet and shows an error banner.
- **iPhone:** opens the system share sheet (expo-sharing, PDF type); no number is asked for.
- The customer's number is never saved or sent to the server.
- `utils/whatsapp.ts` (wa.me text links), `utils/media.ts` (logo URL) and `utils/constants.ts` (DTDC courier URL) are not used by the catalog area.

## 5. Things that look half-built, unused or wrong (observed in code)

1. **MRP** exists in the API, the database and the website, but the Subcategory form has no field for it (`SubcategoryFormScreen.tsx`).
2. **Product `isActive`:** the list shows an "Inactive" badge, but the form has no way to change it; the loaded value is just sent back (`ProductFormScreen.tsx`).
3. **Category `isActive`:** the PATCH endpoint accepts it and the website filters on it, but the app has no control for it.
4. **Category delete** does not exist anywhere.
5. **Product attributes** (technique, color, etc.) are stored, filterable on the website and shown on its product page, but the app cannot set them (comment in `ProductFormScreen.tsx` → `buildPayload`). New products are created with them empty.
6. **Product name goes stale:** it is set only at creation. Moving a product to another subcategory keeps the old name (`updateProduct` only changes the name if one is sent, and the app never sends one).
7. **No way to add, remove or mark damaged barcodes on an existing product.** The endpoint `POST /admin/inventory/products/:id/pieces` exists, but the app has no function calling it.
8. **`getProductStats`** is defined in `api/catalog.ts` but never used. The `category` filter on `listProducts` is never used either.
9. **Subcategory list labels:** the product count is labelled "N piece(s)", and the store price appears twice ("₹X" and "Store ₹X") (`SubcategoryListScreen.tsx`).
10. **Outdated comments:**
    - `api/catalog.ts` (the `AdminSubcategory` type) and `SubcategoryListScreen.tsx` say a subcategory borrows a product or category photo; the backend no longer does this.
    - `schema.prisma` says the catalog PDF is "one per category"; it is one per subcategory.
11. **Catalog PDF screen text** says it includes "every active product's photo". The backend includes only active products that are in stock and have a photo.
12. **Hidden subcategories** can still generate a catalog PDF; there is no visibility check (`catalog-pdf.service.ts`).
13. **Edit-form gaps:**
    - The Category and Subcategory form error text says "Tap Save Changes to retry", but the button is labelled "Save".
    - A photo can only be added after the first save, in both forms.
14. **Product in a hidden subcategory:** when editing it, the subcategory picker shows "Select" (the list hides hidden subcategories), but the existing ID is still sent on save (`ProductFormScreen.tsx`).
15. **Products with `hidden` visibility** (old data) show no selected channel chip, because the form offers only three options.
16. **Barcode normalisation differs:** the app only trims and upper-cases, while the backend also removes inner spaces (`utils/barcode.ts` in FE vs BE).
    - So "NH 001" and "NH001" can both sit in the app's pending list; the server then rejects the batch with `DUPLICATE_IN_BATCH`, which the app shows as a generic error.
    - Codes shorter than 3 characters are not checked in the app and only fail when the server validates the save.
17. **Archived products keep their barcodes blocked:** their pieces still exist, and the server's taken-barcode check ignores whether the product is archived (`claimPiecesForProduct`). The app's pre-check, however, uses scan lookup, which does ignore archived products. So such a code shows as "Added", then the create fails with `BARCODE_ALREADY_ASSIGNED`.
18. **Deleting a subcategory leaves its catalog PDF file in storage:** the database record is removed, but the file's key is not in the list of files to delete (`deleteSubcategory`).
19. **Subcategory delete removes more orders than its comment says:** the comment says it removes unpaid orders that "only ever contained these products", but the code deletes every unpaid order with a line for any of its products, whatever else the order held. `deleteProduct` does the same for one product.
20. **Channel settings don't affect counter sales:** a counter sale (scan-sell) does not check channel visibility or whether the product is active, so "Online only" products still sell at the counter (`resolveAndClaimOfflineSaleItem`).
21. **The "live listings" number and the 5000 cap** count every active product, including sold-out ones (`getProductStats`).
22. **Minor:**
    - The PATCH product response has no available count (it is not passed through `withAvailability`); the app ignores the response anyway.
    - Available count runs one database query per product listed (`catalog.availability.ts`).
23. **Unreachable camera message:** the product form passes a "field already holds a code" message to the scanner, but the scan button is already disabled in that state.
24. **Caption only on Android:** the caption is sent only by the Android direct-to-chat path; the iPhone share sheet sends the file alone (`whatsappPdf.ts` → `sharePdfOnWhatsApp`).
25. **Business rules enforced only in the app:** "photo + at least one barcode required to create a product" is checked only in the app; the backend accepts a product with neither. The default tracking mode also differs: the app sends `serialized`, while the backend default is `quantity`.

|---|---|---|---|
| GET | /admin/categories | ADMIN, STAFF | Category list and form, product form |
| POST | /admin/categories | ADMIN | Category form (create) |
| PATCH | /admin/categories/:categoryId | ADMIN | Category form (edit) |
| POST | /admin/categories/:categoryId/image | ADMIN | Category photo (multipart field `image`) |
| GET | /admin/categories/:categoryId/subcategories | ADMIN, STAFF | Without `page`: full list (Subcategory form, product picker). With `?page&pageSize(≤50)&q`: paged list (Subcategories list). |
| POST | /admin/categories/:categoryId/subcategories | ADMIN | Subcategory form (create) |
| PATCH | /admin/subcategories/:subcategoryId | ADMIN | Subcategory form (edit, prices, hide/unhide, position) |
| DELETE | /admin/subcategories/:subcategoryId | ADMIN | Subcategory delete |
| POST | /admin/subcategories/:subcategoryId/image | ADMIN | Subcategory photo |
| GET | /admin/products?q&page&pageSize(≤100)&category | ADMIN, STAFF | Product list (returns items, total, activeCount, cap, remaining) |
| GET | /admin/products/stats | ADMIN, STAFF | Client function exists but is unused |
| GET | /admin/products/:productId | ADMIN, STAFF | Product form |
| POST | /admin/products | ADMIN, STAFF | Create product (with `barcodes[]`) |
| PATCH | /admin/products/:productId | ADMIN, STAFF | Edit product |
| DELETE | /admin/products/:productId | ADMIN, STAFF | Delete or archive product |
| POST | /admin/products/:productId/image | ADMIN, STAFF | Product photo (replaces the old one) |
| GET | /admin/subcategories/:subcategoryId/catalog-pdf | ADMIN, STAFF | Catalog PDF status |
| POST | /admin/subcategories/:subcategoryId/catalog-pdf | ADMIN, STAFF (10/min) | Generate PDF (returns PDF bytes + `X-Product-Count`) |
| GET | `<status.url>` (public storage URL) | none | Download the existing PDF for sharing |
| POST | /admin/inventory/scan-lookup `{code, exact?}` | ADMIN, STAFF | Product list scanner; product form barcode check (exact) |
| GET | /admin/inventory/products/:productId/pieces | ADMIN, STAFF | Product form barcode list |
| POST | /admin/inventory/products/:productId/pieces `{barcodes[]}` | ADMIN, STAFF | Exists; **not called by the app** |

Requests with a 401 response go through the app's normal token-refresh path. Image uploads and PDF generation do their own refresh and retry (`api/catalog.ts`, `api/catalogPdf.ts`).
